# Game Design

## 1. コンセプト

現代日本を舞台に、東京で働く普通の会社員が釣りにのめり込み、経験・知識・道具・交通手段・人脈を増やしながら、日本中の釣り場と魚へ到達していく釣りハクスラ。

このゲームの中心は「ステージ攻略」ではない。

世界は最初から存在しているが、プレイヤーには金・道具・知識・技量・交通手段・人脈が足りず、行ける場所と狙える魚が限られている。

成長することで、同じ現実世界が徐々に広く見えるようになる。

## 2. プレイヤーファンタジー

開始時の主人公は特別な釣り人ではない。

- 東京近郊在住の会社員
- 仕事の合間や休日に釣行する生活
- 安価な初期タックル
- 徒歩・電車・バス中心
- 釣り経験は浅い
- 知っている釣り場も少ない

数百時間後には次のような姿を目指せる。

- 複数ジャンルのタックルを所有
- 車・SUV・ボート等を所有
- 全国へ遠征
- 数百魚種を捕獲
- 自己記録級・特殊個体を多数記録
- 釣具店、船長、ガイド、メーカーとの人脈
- 大会実績や高い名声
- 地域や魚種について深い知識

## 3. コアループ

1. カレンダー（日時・季節）を確認
2. 天候・季節・時間・潮・釣果情報を見る
3. 釣り場を決める
4. タックルを組む
5. 移動する
6. 釣り場を探索する
7. 魚を探す
8. ヒット・ファイト
9. 捕獲または失敗
10. 経験値・魚データ・釣り場知識・記録を得る
11. 帰宅
12. 装備、資金、名声、知識を更新
13. 次の釣行計画を立てる

「あと1回」「あと1匹」「次の休日はあそこへ」という継続欲を中心に設計する。

### 3.1 ヒット・ファイト（Phase 10）

Fishing combat is decision-driven, not button-spam driven.

ヒットしてからのファイトは、完全ターン制のテキストバトルにする。

- one command = one meaningful battle step（1 コマンド = 1 step。連打では有利にならない）
- fish behaviours are telegraphed（魚の行動は文章の予兆を挟んでから起きる）
- commands are contextual（同じコマンドでも、魚の行動と状態で意味が変わる）
- high tension and slack are both dangerous（張りすぎ = ラインブレイク / 緩みすぎ = フックアウト）
- tackle changes the margin for error（装備は成功率ではなく「失敗の余地」を変える）
- light tackle can still land big fish（Hard gate は作らない。判断が良ければ獲れる）
- small fish fights stay short（小さい魚は 1〜3 コマンド。テンポを守る）
- text is presentation; structured events are domain truth
  （文章は UI の表現。判定は Domain の数値とイベントで行う）

プレイヤーは反射神経ではなく、状況を読んで次の一手を選ぶ。

## 4. 世界設計

### 4.1 日本全体を巨大なゲームワールドとして扱う

一本道のエリア進行にはしない。

例:

- 東京湾
- 多摩川
- 荒川
- 江戸川
- 相模川
- 芦ノ湖
- 相模湾
- 湘南
- 三浦半島
- 房総
- 霞ヶ浦
- 北浦
- 富士五湖
- 伊豆
- 北海道
- 東北
- 北陸
- 東海
- 近畿
- 中国
- 四国
- 九州
- 沖縄
- 離島

地域 > 水域 > エリア > Spot の階層で管理する。

### 4.2 Spot

Spotはゲーム上の最小フィールド単位。

例:

- 河口
- 橋脚
- 流れ込み
- 護岸
- サーフ
- 磯
- 漁港
- 堤防
- シャロー
- ブレイク
- 深場
- 沖根
- 湖岸
- 支流
- 渓流区間

最終的には数百〜1000以上のSpot追加に耐えられる構造にする。

## 5. 魚

魚はゲーム都合だけで配置しない。

可能な限り現実の以下の情報を基礎にする。

- 分布
- 生息環境
- 海水 / 汽水 / 淡水
- 水温
- 水深
- 季節性
- 回遊
- 時間帯
- 潮
- 天候
- 流れ
- 食性
- 餌
- 有効なルアー
- 一般的な釣法
- 平均サイズ
- 最大級サイズ
- サイズ分布
- ファイト特性

最終的に1000魚種以上を扱えるデータ設計を前提とする。

### 5.1 魚種レア度と個体レア度を分離する

魚種そのものの希少性と、その個体の希少性は別物。

例:

- 一般的なマアジ 18cm
- 同じマアジでも45cm超の極端な大型個体

後者は強い価値を持つ。

### 5.2 Individual Fish

ヒット時に魚の個体を生成する。

個体差の候補:

- Length
- Weight
- Condition
- Fight Strength
- Behavior
- Trait
- Sex（必要な魚種のみ）
- Regional Population
- Capture Context

サイズと重量は魚種ごとの現実的な分布モデルを使い、不自然な個体生成を避ける。

## 6. Elite / Special Fish

ファンタジー化はしない。

Eliteは「現実に存在し得る特殊個体」として扱う。

例:

- Trophy: 同種上位クラスの大型個体
- Old: 老成し警戒心の高い個体
- Strong Runner: 遊泳力が高い
- Heavy: 体長に対して重量が大きい
- Scarred: 過去の捕獲痕などを持つ
- Aggressive: 捕食性・反応が強い

さらにごく稀に、その地域で噂になるような記録級個体を設定できる。

「湖の主」のような表現は可能だが、能力は現実の範囲から逸脱させない。

## 7. 移動手段

移動手段は重要な成長要素。

- 徒歩
- 電車
- バス
- 自転車
- バイク
- 軽自動車
- 普通車
- SUV / 4WD
- レンタルボート
- カヤック
- トレーラーボート
- プレジャーボート

交通手段は単なるステータスではなく「アクセス可能なSpot」を変える。

例:

- 車を買う → 駅から遠い河川・湖・磯へ行ける
- 4WD → 山間部等へのアクセス能力向上
- ボート → 岸から届かない水域へ行ける
- 自艇 → 出船場所・時間・海域選択の自由度上昇

## 8. タックル

主要装備:

- Rod
- Reel
- Line
- Leader
- Hook
- Lure
- Bait
- Net
- Waders
- Cooler
- Fish Finder
- Boat Equipment

ファンタジー装備ドロップは採用しない。

魚を釣ったらロッドが落ちる、という構造にはしない。

タックルは購入、中古市場、限定品、カスタム、イベント、人脈等を通じて入手する。

## 9. ハクスラ性

ハクスラの快感を次に置き換える。

### 魚

同じ魚種でも個体が違う。

- サイズ
- 重量
- コンディション
- ファイト
- Trait
- 捕獲場所
- 季節

同じ場所に何度通っても自己記録更新の可能性がある。

### タックル

同じ釣法でも組み合わせを試行錯誤する。

例:

- Long Cast
- Power
- Finesse
- Big Game
- Night
- Current
- Deep
- Surface

現実のタックル構成をゲーム的に理解しやすく抽象化する。

## 10. Knowledge

釣り場ごとにKnowledgeを持つ。

初訪問では情報が少ない。

釣行、観察、店員、船長、SNS、雑誌、動画、地元の釣り人等を通じて情報が増える。

Knowledgeが増えると表示される情報例:

- 地形
- 水深
- 流れ
- ベイト
- 季節パターン
- 有効時間帯
- 魚種
- 実績ルアー
- 雨後の変化
- 潮位との関係

ボウズでもKnowledgeは蓄積する。

## 11. Reputation

Levelとは別軸。

Levelは本人の技量。
Reputationは周囲からの評価・信用。

Reputationで得られるもの:

- 地元情報
- 釣り場情報
- 船宿との関係
- ガイド
- 大会
- 招待
- メーカーとの関係
- テスト品
- 特殊な釣行機会

高Level・低Reputationの無名熟練者も成立する。

## 12. 仕事とお金

### 12.1 仕事の扱い

主人公は普通の会社員だが、**仕事そのものはゲーム化しない**。

仕事が提供するのは、次の背景設定だけである。

- 毎月の安定した収入
- 生活費を差し引いた自由資金

そのため、次は採用しない。

- Career XP / Career Level / 昇進 / 昇給 / 転職 / Job Offer
- Work Skill、釣りSkillを仕事へ転用する仕組み（Cross-Skill）
- 仕事のミニゲーム、評価（Performance）、上司・同僚
- 勤務時間による釣行の制限、通勤、有給

**プレイヤーの釣行を仕事の予定で止めない。** ゲームの中心は常に釣りである。

時間帯・曜日・季節・天候・潮は、釣りの条件（活性・混雑・大会・イベント・
釣り場ルール）として使う。カレンダーはそのための器として持つ。

### 12.2 お金の扱い

Moneyは必要だが、厳しい家計シミュレーションにはしない。

原則:

- 給料は安定して入る
- 通常生活費はまとめて自動処理
- 家賃、税、光熱費などを細かく管理させない
- 軽微な赤字でゲームオーバーにしない
- 釣行不能になるほど厳しい資金不足を常態化させない

Moneyの主な用途:

- タックル
- 交通費
- 車
- 遠征
- 宿泊
- 船
- ガイド
- ボート維持
- 消耗品

お金は「罰」ではなく「次に何を買うか悩むための資源」とする。

### 12.3 釣りと生活の循環

```
釣りへ行く
↓
経験・知識・記録が増える
↓
Knowledge と自己記録が増える
↓
給与と合わせて自由資金が増える
↓
車・遠征費・タックルを確保
↓
さらに釣りの世界が広がる
```

ただし中心は常に釣り。

## 13. 現実性

地域ごとのルールをデータ化できる設計にする。

例:

- 遊漁券
- 禁漁期間
- 禁止区域
- サイズ制限
- 採捕制限
- 釣法制限
- 船舶関連条件

現実の制度は変更され得るため、将来的に source / verifiedAt / validFrom 等を保持できるようにする。

## 14. エンドゲーム

ラスボスは置かない。

目標例:

- 魚種コンプリート
- 地域図鑑完成
- 日本全国遠征
- 自己記録更新
- 記録級魚
- Elite収集
- 大物狙い
- 特定魚種専門
- 大会
- 名声
- タックル収集
- ボート所有
- 離島遠征

プレイヤー自身が次の目標を選ぶゲームにする。

## 15. 絶対に守る方向性

- 異世界化しない
- ダンジョン進行にしない
- 魚をモンスター扱いしすぎない
- レベルだけで地域をロックしない
- 魔法的装備効果を中心にしない
- 現実の魚、生態、釣法、地域差を大切にする
- 現代日本の会社員という生活背景を世界観として保つ
- 仕事は定期収入の背景に留め、ゲームシステムにしない
- お金を過度にシビアな生存管理へ変えない
